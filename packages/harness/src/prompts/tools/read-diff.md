Read patches for a batch of 1–8 related manifest paths (old-path aliases accepted) at the pinned baseline/head, with five context lines. Returns status/path metadata and exact patch fragments with original hunk/line counters. Binary and unsupported content is explicit. Each serialized response is bounded by the configured tool-output limit, including metadata and JSON escaping.

Start a batch with paths and no cursor (or cursor=null). When the response has remaining=true, copy its top-level cursor string exactly into the next call and keep the same paths strings in the same order. The cursor is an opaque token bound to that batch and review attempt, not a page number, byte offset, path or value to reconstruct. Do not change, shorten or invent it. remaining=false and cursor=null mean only this batch is finished; start the next uninspected manifest batch without a cursor. A section's complete=true refers only to that file. A fragment may split an oversized hunk or source line: concatenate patch fields in order, using offsetBytes and hunk.lineOffsetBytes.

If the tool returns "Invalid read_diff cursor or batch", compare your arguments with the last successful call and response. Retry with its exact ordered paths and cursor. If that pair cannot be recovered, restart the affected batch once without a cursor and continue using the newly returned token; this restart is an allowed reason to reread supplied content. For an absent/ambiguous path, copy the manifest's path exactly. If response metadata is too large, start a smaller batch without a cursor. If corrected pagination still fails, inspect relevant head/baseline ranges with read_file, continue other batches and disclose the diff coverage gap. Never retry the same invalid request unchanged or invent revision, context-size or path arguments.
